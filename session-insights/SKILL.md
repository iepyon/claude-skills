# Session Insights

Claude Code のセッションログを解析して、作業サマリー・インサイト・クイズを Markdown で生成するスキル。

## Step 1: 期間を特定する

ユーザーの発言から対象期間を決定する:

| 発言 | `--days` 引数 |
|------|-------------|
| 今日 / 本日 / 今日分 | `--days 0` |
| 昨日 | `--days 1` |
| 今週 / 今週分 | `--days 7` |
| 先週 | `--start YYYY-MM-DD --end YYYY-MM-DD`（先週月〜日）|
| 過去N日間 | `--days N` |
| 日付指定 | `--start YYYY-MM-DD --end YYYY-MM-DD` |

特定のプロジェクトに絞りたい場合は `--project <キーワード>` を追加する。

## Step 2: ログ抽出スクリプトを実行する

```bash
python3 ~/.claude/skills/session-insights/scripts/extract_logs.py --days 0
```

出力はJSON。`sessions` 配列に各セッションの以下の情報が含まれる:
- `slug`: セッションの名前（会話の識別子）
- `cwd`: 作業ディレクトリ
- `start_time` / `end_time`: 開始・終了時刻（UTC）
- `duration_minutes`: セッション時間
- `top_tools`: 使用ツールとその回数
- `messages`: ユーザー発言とアシスタント応答（テキスト抜粋）

## Step 3: Markdown レポートを生成する

抽出データを読んで、以下の構成で Markdown を生成する。

### レポート構成

```
# 作業ログ: YYYY-MM-DD（または 期間）

## 作業サマリー

### [プロジェクト名]
- セッション数・作業時間
- 何をしたか（ユーザーメッセージから読み取る）
- 主なツール使用

## インサイト

作業パターン・学び・注目点を3〜5項目で書く:
- よく使ったツールから見える作業スタイル
- 複数セッションにわたる一貫したテーマ
- 試行錯誤が多かった箇所とその背景
- 今日の成果として特筆すべき点

## クイズ

今日扱った技術・手法・概念に関する知識確認問題を3〜5問作る。

クイズの方針:
- 作業ログに登場した技術・フレームワーク・ツール・手法を題材にする
- 単純な「今日何をしたか」ではなく、その背景にある技術・ビジネスの知識を問う
- 例: EventStorming を使ったなら「Domain Event とは何か」「Orange sticker の意味」を問う
- 例: Pythonスクリプトを書いたなら「argparse の使い方」「JSONL 形式の特徴」を問う
- 例: PRを作ったなら「git rebase と merge の違い」を問う
- 選択肢問題（A〜D の4択）と `<details>` タグで答えを隠す形式にする

### クイズ形式の例

**Q1. EventStorming において Orange sticker（コマンド）が表すのは何ですか？**

A) ドメインイベント（過去に起きた事実）
B) システムへの意図（ユーザーやシステムが行う操作）
C) 外部システムとの境界
D) ドメインモデルのエンティティ

<details><summary>答え</summary>

**B) システムへの意図**

コマンドはアクター（人やシステム）がドメインに対して発する意図・操作を表す。ドメインイベント（紫）の原因となる。

</details>
```

### 時刻の扱い

ログの時刻はUTC。日本時間（JST = UTC+9）に変換して表示する。

## Step 4: ファイルに保存する

カレントディレクトリの `doc/session-insights/` に保存する。
ディレクトリがなければ作成する。

ファイル名:
- 日次: `insights-YYYYMMDD.md`
- 週次: `insights-YYYYMMDD-YYYYMMDD.md`（開始日-終了日）

保存後、ファイルパスをユーザーに伝える。

## 注意事項

- セッションが0件の場合は「該当期間にセッションが見つかりませんでした」と報告する
- メッセージが断片的でも、使用ツールから作業内容を推測する（例: Edit + Bash が多い → コーディング作業）
- サブエージェントのセッションも含まれる場合があるが、`cwd` や `slug` で主セッションを判断する
- クイズの難易度は「その技術を使った経験がある人が答えられる」レベルが適切
