# Q&A まとめ: 2026-04-02 〜 2026-04-16

過去2週間のセッションで質問した内容と回答の整理。

## 1. Claude Code の使い方・機能

### Q. Claude の会話ログはどこに保存される？ (04/08)
**A.** `~/.claude/projects/` 配下にローカル保存されている。`/history` コマンドで過去の会話一覧を確認できる。

### Q. Claude Code で作業フォルダや worktree の場所を表示するには？ (04/07)
**A.** **ステータスライン**を使う。`/statusline` コマンドで表示内容を設定可能。`~/.claude/statusline.sh` にスクリプトを作成し、`model`、`current_dir`、`worktree.name` 等を表示できる。

### Q. ステータスラインをプロジェクトに含めることは可能？ (04/07)
**A.** 可能。`.claude/settings.json` に `statusLine` 設定を書けば、プロジェクトで作業する全員に適用される。スクリプトも `.claude/statusline-command.sh` 等に配置する。

### Q. Sandbox とは？ (04/06)
**A.** Claude Code の Bash コマンド実行時のセキュリティ機能。有効時はファイルシステムやネットワークへのアクセスが制限される。`auto-allow` を有効にすると毎回の確認なしで自動許可される。

### Q. Word を扱うスキルは？ (04/07)
**A.** `document-skills:docx` スキルで .docx の作成・読み取り・編集・操作全般に対応。プラグインとして `document-skills` をインストールすると使える。

### Q. settings.json を更新したが動かない？ (04/07)
**A.** `settings.json` の変更は**セッション再起動が必要**な場合がある。`/clear` して動作確認するか、`$TOOL_INPUT` の形式を確認するテスト用フックを試す。

## 2. アーキテクチャ・設計パターン

### Q. meetup-sample の backend community コンテキストのレイヤー構造は？ (04/06)
**A.** モノレポ（npm workspaces）で `backend/`, `frontend/`, `e2e/` の3パッケージ構成。バックエンドは Express.js + Prisma + SQLite + TypeScript。community コンテキスト内は controllers / usecases / repositories / domain のレイヤーに分かれている。

### Q. イベント作成の権限チェックはどこでやっている？ (04/06)
**A.** **ミドルウェア層**で実施。ルート定義で `requireAuth`（JWT認証）→ `requireCommunityRole`（コミュニティ内ロール確認）の順に適用。ロールがなければ `403 FORBIDDEN` を返す。UseCase層では権限チェックしない。

## 3. EventStorming / DML 関連

### Q. SAME 境界でポリシーはある？ (04/08)
**A.** ある。`TX: SAME` は「同じトランザクション内で即座に反応する」ポリシー。例えば参加申込 → 定員チェック → 承認/キャンセル待ち が1トランザクションで一気に起きる。

**SAME vs EVENTUAL の判断基準:**
| | TX: SAME | TX: EVENTUAL |
|---|----------|-------------|
| 用途 | 整合性が必須 | 結果整合性で十分 |
| 例 | 在庫確保・決済 | 通知・レコメンド更新 |

### Q. ハッピーパスはコンテキストでレーンを作って図を大きく見えるようにできないか？ (04/07)
**A.** 可能。BC（Bounded Context）ごとに横帯（swim lane）を作り、フローが各レーンを行き来する形でレイアウトできる。

### Q. 文章作成の順序 — ストーリー先 → EventFlow → DML で整合性に問題はある？ (04/08)
**A.** 問題なし。むしろ「全体像把握」のゴールに合っている。
- ストーリーが「何が起きるか」の共通理解を先に作る
- Event Flow図はストーリーから機械的に導出できる
- DMLはストーリーと図で合意した内容を形式化するだけ

**注意点:** ストーリーを書くにはCMD/POLICYの区別が最低限必要。イベント一覧確定後、チェーンの骨格（CMD→EVT→POLICYの1行メモ）だけ軽く確認してからストーリーを書くとスムーズ。

## 4. ドメイン知識（靴EC）

### Q. 5足注文して3足キープしたとき、購入確定の支払いはどうなる？ (04/10)
**A.** 2パターンある:

| パターン | 仕組み | メリット | リスク |
|---------|--------|---------|--------|
| **A: 与信確保型** | 注文時に全額与信 → キープ分だけ決済 → 残りは与信解除 | 未払いリスク低 | カード会社との調整が必要 |
| **B: 後払い型** | 注文時は登録のみ → キープ確定後に請求 | UXがシンプル | 踏み倒しリスクあり |

## 5. 開発プラクティス

### Q. 循環複雑度はすぐに判定できる？ (04/14)
**A.** 非常に速い。ESLintの `complexity` ルールはAST走査（構文木のブランチ数カウント）なので:
- ファイル1本: **50〜200ms**
- プロジェクト全体（TGrid規模）: **1〜3秒**

ループ内リアルタイムチェックでもpre-commitでも問題ないスピード。

### Q. テスト実行する前にバックエンドの起動を忘れていない？ (04/06)
**A.** 指摘通り。E2Eテストはサーバーの事前起動が必要な場合がある。`d up` でコンテナ起動 → `d dev` でバックエンド+フロントエンド起動 → E2E実行という手順を踏む。

### Q. ワークツリーを使った？ (04/13)
**A.** メインリポジトリ上で直接ブランチを切って作業していた。ワークツリーは使っていなかった。

## 6. ワークショップ企画

### Q. AIエージェントを使ったワークショップの学習目標（ルーブリック）を整理して (04/03)
**A.** 以下の軸で整理:
- **AIエージェント**: チャット型との違いの区別、ゴール提示での依頼、具体例指定、プランモード活用
- **JavaScript/CSS/HTML**: 基礎文法を使った自己紹介ページ作成
- **AI学習の注意点**: 学習が維持されるパターンと破壊されるパターンの区別
- **説明責任**: AIの使い方の説明、成果物のメカニズム説明、不明点の表明と質問
