# 想定問答の実走評価 — エージェントに解かせる手順

バンドル（`assets/doc/wiki/`）が想定の問いに答えられるかの検査は、2つの半分でできている。

| 半分 | 何を確かめるか | どこにあるか | いつ走るか |
|---|---|---|---|
| 決定論 | 答えのアンカーが実在し、検索語で届くこと | `__tests__/answerability.test.ts` | CI（毎回） |
| 非決定論 | **問いだけを渡された読み手が、実際に答えへ辿り着くこと** | この手順 | 手動（問いや本文を大きく動かしたとき） |

**この手順を CI に入れてはいけない。** 理由は [B-10](../BACKLOG-WONTDO.md) と同じ —
決定論的な検査が効いている場所に、非決定論的な工程を戻さない。エージェントの答えは
走らせるたびに揺れるので、赤くなっても「壊れた」ではなく「揺れた」かもしれず、
その区別に人の目が要る。人の目が要る検査は、緑を機械に言わせてはいけない。

逆に、この手順で**しか**見つからないものがある。決定論の半分は「アンカーが有る・語が有る」
までしか言えず、**読み手がその語で探すか・辿り着いた答えを答えだと分かるか**は言えない。
`questions.yaml` の keywords が答え側の語彙に寄せてあるのはそのためで、読み手が実際に
使う語とずれていれば、テストは緑のまま実走だけが外れる — その外れ方が本文の直しどころである。

## 手順

1. **新しいエージェントを1体立てる。** このリポジトリの事情を何も知らないこと
   （同じセッションの続きで解かせると、本文を書いた記憶で答えてしまい、
   バンドルの外の知識と区別できない）。

2. **渡すのは2つだけ**: バンドルのディレクトリ（`assets/doc/wiki/` 全体。読み取り専用）と、
   `questions.yaml` の **`q` 列だけ**。`answers` / `keywords` / `note` は伏せる
   （答え合わせの鍵を渡したら検査にならない）。`expect: gap` の問いも伏せずに混ぜる —
   gap の問いに答えが返ってきたら、それは「本文に無い答えを作った」兆候である。

3. **回答の形式を指定する。** 問いごとに:
   - 答え（本文の言葉で簡潔に）
   - 引用アンカー（`デッキ名.md#スライドID` の形。目録・履歴なら `index.md` / `log.md`）
   - 辿り着けなければ「見つからない」と明言（それらしい答えの創作を禁じる）

   プロンプトの雛形:

   > このディレクトリは OKF のバンドル（markdown のデッキ集合）です。`index.md` が目録です。
   > 以下の問いに、**このバンドルの中身だけ**を根拠に答えてください。
   > 問いごとに「答え（1〜3文）」と「根拠のアンカー（`デッキ名.md#スライドID`）」を返し、
   > バンドルの中に答えが見つからない問いは、推測せずに「見つからない」と答えてください。

4. **採点する。** 問いごとに、返ってきたアンカーを `questions.yaml` の `answers` と突き合わせる:
   - **一致** … 答えられている。
   - **不一致だが答えは正しい** … 本文の別の場所が同じことを言っている。重複の兆候
     （一枚一義に反していないか）か、`answers` の書き漏れ。どちらかを直す。
   - **不一致で答えも外れ** … keywords が答えへ導けていないか、本文が問いに答えていない。
     本文を直すか、直さないと決めたなら問いを `expect: gap` に落とす。
   - **gap の問いに答えが返った** … 出典のアンカーを確かめる。実在しなければ創作
     （このバンドルの外の知識）なので、問いは gap のままでよい。実在したら
     `answers` に書いて answered に上げる。

5. **結果を残す。** 外れた問いは `questions.yaml` の修正（gap 化・answers 追記）か
   本文の修正か、どちらでもなければ BACKLOG の項目として残す。
   「答えられない問いは、そのまま置く」（patterns-wiki.md の `街灯の外へ`）。
