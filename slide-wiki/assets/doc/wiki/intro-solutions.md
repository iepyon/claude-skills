## 名前は増えたのに、LLM との境が引けていない
<!--id:困りごと-部品-->
RAG、エージェント、MCP、ファインチューニング。名前はもう全員が知っている。
それでも「これ、LLM でできますか」という問いには、いまだに答えが割れる。

割れるのは、どれも「AI っぽいもの」として横並びに置かれているからである。
実際には、RAG は LLM に**材料**を足す部品で、エージェントは LLM を**回す**外側の系で、
MCP は LLM が触る**口**の規格である。足す場所が違うので、そもそも比較の対象ではない。

比較の対象でないものを並べて選ぼうとするから、決まらない。
決まらないまま全部入れると、どれが効いているのかも分からなくなる。

<!--takeaway-->
横並びの一覧では選べない。基準点を一つ決める必要がある

## ねらい — 基準点を LLM に固定する
<!--id:ねらい-部品-->
このデッキは、13の部品を**すべて LLM との差分**で書く。
一枚ごとに聞くのは二つだけである。**LLM に何を足すのか**、そして**LLM に何が残るのか**。

前者だけを書いた資料は多い。だが足すものだけ分かっても、役割の線は引けない。
線が引けるのは、その部品を入れたあと LLM の仕事が何に縮むかを書いたときである。

もう一つ決めるのは、部品を排他の選択肢として扱わないことである。
[[patterns-solutions/RAG|RAG]] と [[patterns-solutions/ファインチューニング|ファインチューニング]] は
どちらを選ぶかではなく、事実と振る舞いという別の口を塞いでいる。

## LLM に無い5つ
<!--id:五つの欠け-->
<!--numbered-list:bar-->
### 記憶
呼び出しをまたいで覚えない。前回の話は、渡さなければ無かったことになる
### 手
外の世界に触れない。読むことも書くことも、与えられた口を通してしか起きない
### 段取り
一往復で終わる。途中で止まる・戻る・落ちた所から再開する、がどれも無い
### 同じ答え
同じ入力に同じ出力が返る保証が無い。通ったのが規則か運かを区別できない
### 数の勘
数を数えず、返る確率も較正されていない。0.8 という数字に意味は無い

<!--takeaway-->
以降の12の部品は、すべてこの5つのどれかを塞ぐためにある

## 上から順に聞いていく
<!--id:順番-部品-->
<!--numbered-list:circle-->
### 決まる判定か
数えられる分岐ならルールベースに書く。LLM に残るのは手前の解釈だけ
### 表に並ぶ予測か
正解付きの過去があるなら機械学習モデル。LLM は入口と出口に回る
### 知らない事実が要るか
要るなら RAG。棚が空なら、先に LLM Wiki とデータ基盤のほうを作る
### 外の世界に触るか
触るなら MCP で口をそろえる。道具ごとの配線は書かない
### 順番は事前に描けるか
描けるならワークフロー。描けない一歩にだけ AI エージェントを置く
### 一人分の文脈に入るか
入るなら分けない。入らず、道が独立している時だけマルチエージェント

<!--takeaway-->
下まで降りるほど、費用と、失敗の見えにくさが上がる

## 部品は排他ではない — 重ねて使う
<!--id:重ねる-部品-->
実際に動いている系は、たいてい一つの部品では説明できない。
たとえば問い合わせの一次対応なら、口を [[patterns-solutions/MCP|MCP]] でそろえ、
社内規定は [[patterns-solutions/RAG|RAG]] で引き、返信の型は
[[patterns-solutions/ファインチューニング|ファインチューニング]] で固定し、
返す前に [[patterns-solutions/ガードレール|ガードレール]] を通し、週次で
[[patterns-solutions/Evals|Evals]] を回す、という重ね方になる。

重なるのは、それぞれが**別の欠け**を塞いでいるからである。
逆に、同じ欠けを塞ぐ部品を二つ入れているなら、どちらかは効いていない。
[[patterns-solutions/RAG|RAG]] を入れたうえで事実をファインチューニングで焼くのが、その典型である。

<!--takeaway-->
迷ったら「これはどの欠けを塞ぐのか」を聞く。答えが重なったら、片方は要らない

## 撒く — まだ決めていないこと
<!--id:撒く-部品-->
5つの欠けは、モデルの側でも埋まりつつある。文脈は伸び、道具の呼び出しは内側に入り、
やり切れる仕事の長さも伸び続けている。塞ぐために足した部品は、埋まったぶんだけ余る。

余ったことに気づくのは難しい。動いている部品は、外していい理由が誰にも見えないからである。
だから足す時に、**何を塞ぐために入れたのか**を書き残しておく必要がある。
書いていなければ、外す判断はできない（[[patterns-llm-wiki/年輪|年輪]]）。

残るもう一つは、部品をいくら足しても埋まらない側である。
何を問うかと、間違えた時に誰が引き受けるかは、どの部品にも書いていない
（[[patterns-delegation/誰が謝るか|誰が謝るか]]）。

<!--takeaway-->
いま入っている部品のうち、塞ぐ理由をもう説明できないものはどれだろうか
