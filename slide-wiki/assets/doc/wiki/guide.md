# リンクで辿るスライド

ページめくりだけではない、もう一つの読み方

---

## 何ができるか
<!--id:概要-->
<!--icon-cols-->

### ホバーで覗く
<!--icon:mi:visibility-->
移動せずに行き先を確かめる。

### リンクで飛ぶ
<!--icon:mi:link-->
戻るボタンで来た道を戻れる。

### 逆から辿る
<!--icon:mi:swap_horiz-->
このスライドを指している側の一覧が出る。

---

## 書き方
<!--id:書き方-->
<!--table-->

| 書くもの | 意味 |
| --- | --- |
| `[剪定](patterns-wiki.md#剪定)` | サイト内のスライドへのリンク |
| `[第2部](patterns-wiki.md)` | デッキ全体へのリンク。その1枚目に着く |
| `[ラベル](https://…)` | 外部リンク |
| `<!--id:foo-->` | スライドに ID を付ける |

<!--takeaway-->
リンクは普通の markdown だけ。ID を省くと見出しから自動生成される

---

## リンクの書き方
<!--id:解決順-->
<!--numbered-list:circle-->

### デッキ名から書く
`デッキ名.md#スライドID`。デッキ名は拡張子を除いたファイル名そのもの。

### 同じデッキの中でもデッキ名を書く
`#スライドID` だけにしない。書き方が1つなら、どこから見ても行き先が同じになる。

### 見つからなければ未解決として残る
勝手に近いものを選ばない。サイドバーに一覧が出る。

### 独自の記法は無い
そのまま GitHub で開いてもリンクとして飛ぶ。他の道具にも変換なしで渡せる。

<!--takeaway-->
書き方を1つに絞ると、「どちらを指しているか決められない」が起きなくなる

---

## 操作
<!--id:操作-->
<!--grid:2x2-->

### ← →
順に送る。デッキの境界も越えるので、サイト全体を通しで読める。

### スライドの左右端をクリック
同じ送りをタップでも。端のリンクはリンクとして働く。

### リンクにホバー
行き先を縮小表示。プレビューの中のリンクも辿れる。Esc で閉じる。

### 戻る
辿ってきた道を1つ戻る。ブラウザの戻ると同じもの。

---

## 何に使えるか
<!--id:使いどころ-->
### パターン集
互いに参照し合う知識は、順番に並べると関係が消える。
実例は [第1部](intro-wiki.md#育てる理由) から辿れる。

### 育っていくメモ
書き足すたびに構造が変わるものは、目次を固定できない。
[けもの道](patterns-wiki.md#けもの道) がまさにその話。

### 発表と参照の両立
発表では順に送り、後から読む人はリンクを辿って回る。
1つの成果物で両方を満たせる。これが [収穫](patterns-wiki.md#収穫) というパターンである。
