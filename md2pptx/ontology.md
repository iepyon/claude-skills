# md2pptx スライド Markdown オントロジー

md2pptx が読む Markdown の構造の全文リファレンス。**この文書は生成物**で、正本は
[ontology.yaml](ontology.yaml)。書き方の要約は [SKILL.md](SKILL.md) にある。

## md の骨格要素

| 要素 | 記号 | 説明 |
|---|---|---|
| `deck`（デッキ） | — | 1つの Markdown ファイル。`---` で区切られたスライドの列。 |
| `slide-break`（スライド区切り） | `---` | スライドの境目。行全体が `---` のときだけ区切りになる。 |
| `title-slide`（タイトルスライド） | `#` | H1 で始まるスライド。直後の本文行がサブタイトルになる。 |
| `content-slide`（コンテンツスライド） | `##` | H2 で始まるスライド。レイアウトは directive で選ぶ（無指定なら Default）。 |
| `section`（セクション） | `###` | スライド内の区画。何を意味するかは選んだレイアウトの slots が決める。 |
| `subsection`（サブセクション） | `####` | 区画の中の行ラベル。CustomerJourney と PatternLanguage だけが使う。 |
| `image`（画像） | `![alt](src)` | 行まるごとの画像参照。中身は生成時に読み込んで埋め込む。 |
| `body`（本文） | — | 見出しに属する本文行。`- ` `* ` `+ ` の箇条書きと `1. ` の番号付きリストを含む。 |

- `deck` — 文書全体の frontmatter は持たない。先頭の `---` もスライド区切りとして読まれるので、 `---\nname: x\n---` と書くと1枚目が「name: x」だけのスライドになる。

- `title-slide` — デッキ名（Wiki のサイドバー見出し）は先頭のタイトルスライドから採られる。

- `image` — パスは**その md ファイルからの相対**。図解の枠を持つレイアウト（WikiPattern）だけが読み、 他のレイアウトでは描かれない（lint が報告する）。外部ファイルにしてあるのは、 **md をそのまま GitHub で開いても図が絵として表示される**ようにするため — 図の中身を md に書き込むと、読み手には SVG のソースが見えるだけになる。

- `body` — PPTX はネイティブのバレット/自動番号、HTML は CSS 疑似要素で記号を描く。 **リテラルの `•` を書いてはいけない**（記号が二重に表示される）。ネストは1階層のみ。

## 注釈ディレクティブ

| 注釈 | 記法 | 効くレイアウト | 説明 |
|---|---|---|---|
| `id` | `<!--id:<slug>-->` | すべて | スライドの ID。`[[…]]` の解決先であり HTML の `#hash` でもある。 |
| `icon` | `<!--icon:mi:<name>-->` | IconColumns・IconCards・Steps | セクションのアイコン。`mi:` 接頭辞で Material Icons、それ以外は絵文字。 |
| `takeaway` | `<!--takeaway-->` | Default・LeftRight・TopBottom・Grid・IconColumns・IconCards・Steps・NumberedList・TextOnly・Table・WikiPattern | スライド末尾の出典・まとめ。マーカーの次の行以降が本文になる。 |

- `id` — 省略するとスライドタイトルの slug を採り、衝突したら連番（`-2`）を付ける。 採番は parser/slide-ids.ts が一括で行う。

- `icon` — 効くのは annotations に icon を挙げたレイアウトだけ。他では黙って捨てられる。

- `takeaway` — 効くのは annotations に takeaway を挙げたレイアウトだけ。

### PatternLanguage

- ディレクティブ: `<!--pattern-language-a-->`
- `_tag`: `PatternLanguageOverview`（プラグイン `pattern-language`）
- 説明: パターン・ランゲージ。1ブロックから概要ページ + 詳細ページの2スライドを生成
- 効く注釈: `id`
- 文字数上限: **1024**（既定の上書き）
- 生成されるスライド: `PatternLanguageOverview` → `PatternLanguageDetail`
- メタ: `pattern-meta`（下記「メタ」節）
- ディレクティブ直後の本文: メタ（`key: value` の並び）。最初の `###` でメタ相が終わる。

このスキルで唯一 `key: value` のメタを持つレイアウト。最初の `###` までがメタ、
それ以降が本文。本文の節名も語彙で決まる（語彙外の節は中身ごと黙って捨てられる）。

| スロット | 記号 | 個数 | 見出し | 本文 | 説明 |
|---|---|---|---|---|---|
| `sections` | `###` | `1..n` | 語彙 `pattern-sections` | `free` | パターンの節。節ごとに本文の読まれ方が違う（語彙の説明を見る）。 |
| `example-items` | `####` | `0..n` | 自由 | `free` | 「具体例N：…」節の中の小項目。 |
| `diagram` | `` ```pattern-diagram `` | `0..1` | 自由 | `none` | 概要ページの左下に置く SVG。フェンスの中身をそのまま図として描く。 |

```markdown
<!--pattern-language-a-->

name: 反証条件を先に書く
category: 仮説検証

### 問題・なぜ必要か
後から基準を動かせると、どんな結果も「支持された」と読めてしまう。
### 何をするのか
- 反証条件を一文で書く
- 実験の前に確定させる
### 期待結果
結果の解釈が一意に定まる。
```

### WikiPattern

- ディレクティブ: `<!--pattern-->`
- `_tag`: `WikiPattern`（プラグイン `wiki-pattern`）
- 説明: Wiki のパターン1件。左に 状況/問題/解決、右に SVG の図解
- 効く注釈: `id`・`takeaway`

**図解は必須。** SVG は md に書き込まず、**別ファイルに置いて `![…](….svg)` で参照する**
（書き忘れたスライドは lint が報告し、変換でも止まる）。パターン・ランゲージは構造を
一目で掴ませる形式なので、絵の無いパターンを置けないようにしてある。
ファイルにするのは、md をそのまま GitHub で開いたときに図が絵として表示されるため。
SVG 側は `viewBox` と、それに合った `width` / `height` を**実寸で**名乗ること
（md での表示サイズになる）。埋め込むときは 100% に読み替えるので、
スライド上では枠いっぱいに伸びる。

| スロット | 記号 | 個数 | 見出し | 本文 | 説明 |
|---|---|---|---|---|---|
| `sections` | `###` | `3` | 語彙 `wiki-pattern-sections` | `free` | 状況・問題・解決の3枠。左カラムに上から積まれる。 |

## メタ（`key: value`）

### パターンのメタ（`pattern-meta`）

- レイアウト: `PatternLanguageOverview`
- 書き方: `key: value` を1行ずつ。最初の `###` でメタ相が終わる。
- 未宣言キーの扱い: **warning**

値の `"…"` と `[…]` は剥がされ、`\"` はアンエスケープされる。
未宣言のキーは黙って捨てられるので、増やすときは必ずここへ宣言する。

| キー | 必須 | 種別 | 説明 | 例 |
|---|---|---|---|---|
| `number` | 必須 | `text` | パターン番号。目次(batch-html)がこれと name で項目を作る。 | `12` |
| `name` | 必須 | `text` | パターン名。概要ページの見出しになる。 | `反証条件を先に書く` |
| `category` | 省略可 | `text` | 分類。 | `仮説検証` |
| `stage` | 省略可 | `text` | 適用段階。 | `CPF` |
| `oneliner` | 省略可 | `text` | 一行要約。概要ページのリード文になる。 | `何が起きたら崩れるかを、実験の前に一文で決める` |
| `difficulty` | 省略可 | `int` | 難易度。未指定は 0。 | `3` |
| `frequency` | 省略可 | `int` | 頻度。未指定は 0。 | `5` |
| `related_patterns` | 省略可 | `list` | 関連パターン。カンマ区切り（`[...]` で囲んでもよい）。 | `[P-03, P-07]` |
| `takeaway` | 省略可 | `text` | まとめ。このレイアウトは `<!--takeaway-->` を使わずここで書く。 | — |
| `reference` | 省略可 | `text` | 出典。 | — |

## インライン記法

| 書き方 | 意味 |
|---|---|
| `**text**` | 太字 |
| `*text*` | 斜体 |
| `` `text` `` | インラインコード |
| `[ラベル](https://example.com)` | 外部リンク。HTML は `<a>`、PPTX はハイパーリンク。 |
| `[[slide-id]]` | 内部リンク。表示テキストは ID そのまま。解決できなければ素のテキストになる。 |
| `[[slide-id\|表示テキスト]]` | 表示テキストを指定した内部リンク。 |

効くのは `section-heading`・`section-body`・`takeaway`。プラグインがテキストを直接描く箇所（テーブルのセル・引用本文・ステップのラベル等）では `[[…]]` はそのままの文字として出る（BACKLOG B-22）。

## 制限

- 1スライド **1000文字**を超えると ValidationError。本文と見出し（Markdown 構文を除く）。リンクは表示ラベルだけを数え、URL は数えない。
- 読みやすさの目安は **240文字程度**（ツールでは強制しない）
- PatternLanguage だけは **1024文字**まで（レイアウトごとの上書き）
- `CodeDisplay` は文字数を数えない（タイトルのみ）

上限はレイアウトごとに `max-chars` で上書きできる。超過は ValidationError で止まる。
上限の中でも読みやすさの目安は 240 文字程度で、これはツールでは強制しない。
