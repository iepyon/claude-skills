# 日本語技術文書の文章規範

原稿が満たすべき条件は三つ。
**論理的**（段落単位で追え、飛躍がない）、**わかりやすい**（前を読み返さずに済む）、**親しみやすい**（平易な語で書かれ、読者を突き放さない）。

## 親しみやすく書く

読み通せることを、正確さと同じ優先度で扱う。

- 一文を短く保つ。修飾の入れ子を重ねず、長い修飾は文を分けるか後置する。
- 漢語を積み重ねず、和語の動詞で言う。「変更容易性の担保を企図する」ではなく「変えやすくしておく」。
- 読者が知らない前提を飛ばさない。一言添えてから先へ進む。
- 抽象を述べたら、直後に具体を置く。
- 行為者を主語にした動作の連なりで書く（「調査して特定してくれた」）。結果の羅列や受動態（「特定され、判明した」）にしない。
- ひねった慣用表現（「知識を体に入れる」）、一意に定まらない比喩、術語の響きの流用（人間までの連なりを「経路」と呼ぶ）を避け、平易な動詞でそのまま言う（「身につく」「届くまでの流れ」）。
- 命令調（「〜してはならない」）より、作業者の判断として書く形（「〜するわけにはいかない」）を選ぶ。
- 軽い補足や評価は括弧書きで添えてよい。主張の様式を宣言する前置き（「標語として言い換えれば」）も使ってよい。

## 論証

- 一段落一トピック。最初の文で話題がわかること。場面（調査、報告、検証、評価）が混ざった長い段落は一歩ずつに割る。段落の先頭で前段落との論理関係を接続表現で示す（「であれば」「実際」「しかし」）。
- 一方向に進める。結論を出してから反論を処理して結論を言い直す往復をせず、反論と疑念を片付けてから結論を一度だけ置く。
- 例への弁明や前方参照（「後の章で扱う」）は、論証が一段落した位置（段落末、節末、次節の冒頭）に置く。前方に逃がした論点は必ずそこで回収する。
- 新しい概念を辞書型断定（「XはYである」）で始めない。導入文、働きと差分、必要なら定義、の順。節の中心語は、使う前に定義と対象範囲を述べる。
- 読者が立てそうな誤読は明示的に否定してから本当の理由を述べる（「その理由は『〜だから』ではない。〜だからだ」）。「AではなくB」には根拠を一文添える（反実仮想が使えることが多い）。否定する命題は「」で正確に書き出し、漠然とした否定（「何もかもが解決するわけではない」）で済ませない。
- 譲歩（「確かに〜」）は事実の確認にとどめる。あとで訂正する内容を著者の声で断定すると自己矛盾になるので、通説や読者の声に帰属させる（「〜と要約できてしまうかもしれない」）。譲歩や限定のあとは必ず論を進め、逆接で終えて宙吊りにしない。
- 山場で効かせたい情報（数値、固有の事実）を手前の段落で先出ししない。

## 論証の厳密さ

書き上げたら、読み手の反論を先回りして点検する。

- 推量、可能性、読者の疑念、作中人物の認識、反実仮想は不確実性を保つ。断定に直せるのは本文内の根拠で命題が確定している場合だけ。「かもしれない」を削るのは、根拠なく主張を弱めているときに限る。
- 検出・保証・解決を「必ず」できるかのように書かず、条件付きで述べる（「〜しやすい」「〜が成り立つときに限り」）。
- 区別すべき対象（別々の決定、別々の原因、種類の違う問題）を一括りにしない。複数の要因を単一の原因に還元せず、どの道具がどれを説明するのか対応づける。
- 因果には機構を一文添える。「AだとBになる」で止めない。
- 挙げた例が主張の全体を支えているか確かめる。一部しか支えないなら、主張の範囲を例に合わせて狭める。
- 章・節をまたいで概念の分類・定義・地位を揃える。ある節で「人間が決める」としたものを、別の節で「チームで合意する」と書かない。

## 読者の負荷と誠実さ

- 後で参照しない固有名（ファイル名、関数名、識別子）や装飾的な精度（時刻、HTTP ステータス、カバレッジ率）を出さない。「仕様書」「金額計算のユーティリティ」で済ませる。
- 抽象的な言い回しの指す先が一意に決まらないなら、丸括弧の同格挿入でその場で特定し、前を読み返させない。
- 導入や例の節では、その節の問い・帰結に関係しない詳細を落とす。議論に必要な具体は残す。
- 新しい例を足すときは、前の例と何が違い、なぜもう一つ必要なのかを前置きする。
- 例が作為的に見えうるなら隠さず、疑念を先回りして認める。根拠は著者の断定ではなく、読者自身の経験に訴える一般的事実に求める（「この症状は珍しくないだろう」）。確認していないことを、確認したかのように滑らかに書かない。

## 視点と語り

- 対象を指す語は具体的に選び、「AI」「ツール」でぼかさない。術語（K、契約、不変条件）を導入したら以後はその語で通し、曖昧語に後退しない（定式化前の導入語としては使ってよい）。訳語は分野の慣用に従う（プッシュ通知は「配送」ではなく「配信」）。
- 読者を「あなた」と呼ばず役割名（「開発者」「読者」）で書く。二人称は場面への導入（「〜としよう」）や章・本の結びなど要所にとどめる。架空の人物設定（「入社2年目のエンジニアが」）を無意味に冠しない。
- 人物そのものは原綴りで書く（Lehman、Bainbridge）。歴史上の人物や、人名を冠した概念の定着名は、日本語のカタカナ通称を使う。

## 演出と冗長

演出は全面禁止ではなく節度の問題。修辞は、それが効果を生む箇所にだけ置く。

- 同じ主張を言い換えて繰り返さない。隣接する節が同じことを別角度で述べているなら片方に吸収する。場面の描写直後に内容を要約し直さず、意味づけの一文だけを置く。
- 数文の議論を一文に圧縮できるなら、圧縮した一文だけを残す。読者が自力で補える中間段階は書かない。導出を展開しなくても伝わるなら、構造に名前を与えて言い切る。
- 同じ論理的役割を持つ並列の事実は一文にまとめ、その地位は文頭の語で示す（「当然、経理部の月次処理も顧客の支払いも〜」）。
- 接続や評価のためだけの文（「それ自体はよいことである」）、著者の立場の弁明（「本書もそれを否定しない」）、未導入の概念や文書名の先出しを置かない。
- 想像上の読者との問答や、読者の反応を演じる形（「〜と感じたかもしれない。そのとおりである」）を修辞に使わない。譲歩は地の文で簡潔に行い、読者の疑問は疑問文のまま書く。読者が抱きそうな発想をメタな枠取り（「〜という発想である」）で紹介せず、直接書く。
- 溜め（「ここには〜が潜んでいる」）、修辞疑問、決め台詞の独立段落、「AではなくBだった」の対句、劇的な転回、危険を煽る帰結の列挙を多用しない。段落内の短い体言止め（「ここまでわずか数十秒。」）は山場に限り使ってよい。
- 太字強調は、誤読を防ぐ否定や節の帰結など論理の要所に限り、一節に一、二箇所まで。ほかは文の順序と構造で際立たせる。
- 本文内の根拠で確定していることは、弱い述語（「有効な対策であり」）で済ませず言い切る（「活用において必須であり」）。不確実性を表す弱い述語、語調を整える緩和（「必須だと言ってもいい」）、リズムを作る接続表現（「しかし一方で」）は残す。

## LLM 口調

論点を増やさず「ちゃんと書いている感」だけを足す型を使わない。
本書の術語（本質的複雑さ、回収、判断の配置など）を議論に使うのはよく、空虚な装飾として使うのが問題である。

| 型 | 使わない言い回し |
|---|---|
| 予告と総括 | 重要なのは〜である／本章では〜を扱う・探求する／ここでは〜について見ていく／まとめると／要するに（直前の言い換えだけのとき）／〜に他ならない |
| 姿勢の宣言 | 正面から扱う・回収する・見る・書く・立てる |
| 空虚な形容 | 不可欠／核心的／鍵となる／根本的な／多角的／包括的／総合的 |
| 空虚な動詞 | 掘り下げる／深掘りする／言語化する／触れる／言及する |
| 中身のない接続 | 〜において／〜という側面から／〜の観点から／「さらに」「また」「加えて」の連打 |
| 空の強調と緩和 | 非常に／極めて／大いに／〜と言えるだろう（根拠なく弱めるとき） |

悪い例：「この前提を、ここで正面から回収する」「多角的に分析すると、重要なのは〜である」
良い例：「ここで、この前提を回収する」「評価の核心は、正しさを誰が知っているかにある」

## 表記

- 一文ごとに改行する。段落の区切りは空行で示す。
- コード、差分、ログ、設定ファイルの断片はコードブロックに入れる。
- 用語の由来や定式化の名称など、本筋から一段外れる補足は脚注（`[^ラベル]`）に降ろす。
- 用語を初めて定義・導入するときは太字にする。すでに導入した語を話題として指すとき、引用、通称には「」を使う。用語と定義を並べる箇条書きは全角コロンで「**用語**：説明」と書く。
- ダッシュ（em ダッシュ `—`、horizontal bar `―`、2倍ダッシュ「——」）を日本語の地の文・見出しで使わない。同格・補足の挿入は丸括弧（）に、言い換え・敷衍は句点で二文に分けるか読点でつなぐ。範囲を示す en ダッシュ `–`、英語の複合語（`Curry–Howard`）、コードブロック、書誌情報は対象外。
- 中黒（・）を日本語の並列で使わない。単一の固有名詞の内部では使ってよい。

## 見出し

- その節が答える問い、または扱う対象を指す具体的な句にする。疑問形でも名詞句でもよく、本文のトーンに合うほうを選ぶ。
- 手順だけの見出し（「例に戻す」「〜を読み直す」）や、情報量のない見出しにしない。
- 節の結論を言い切る「セリフ」にせず、見出しの時点で読者がオチを知る状態を避ける。
- 区切り線（罫線 `─` やダッシュ類）で「種別──主題」のように二要素を詰め込まず、単一の自然な句にする。コラム見出しも「基礎」「補足」のような種別名で済ませず、「同値関係としての分類」のように内容を特定する。
